# 图形学课程项目构建计划

## 一、项目概述

### 1. 项目名称
基于 `OpenGL Core Profile + C++ + GLFW/GLAD + ImGui` 的室内三维场景实时渲染系统

### 2. 项目目标
实现一个具有明确室内或半室内空间感的三维场景，支持通用模型加载、纹理材质、实时光照、阴影映射、第一人称漫游和 GUI 参数调节，并在此基础上加入至少一个动态或光影增强效果。

### 3. 项目定位
本项目采用底层图形 API 与 C++ 自主实现三维场景渲染流程，不依赖 Unity、Unreal Engine、Godot 等成熟游戏引擎，重点体现图形学基础能力、资源组织能力与实时渲染实现能力。

## 二、技术路线

### 1. 技术栈
- `C++`
- `OpenGL Core Profile`
- `GLFW`
- `GLAD`
- `ImGui`
- `OBJ` 模型格式
- `PNG/JPG` 纹理格式

### 2. 选型理由
- `OpenGL` 学习资料丰富，适合作为课程项目的底层渲染 API
- `GLFW + GLAD` 组合成熟，便于快速完成窗口、输入与函数加载
- `ImGui` 适合快速构建实时参数调节界面
- `OBJ + PNG` 资源管线简单清晰，方便模型同学与程序同学协作

## 三、验收导向目标

项目优先满足以下最小可验收能力：

- 能加载并显示 `OBJ` 模型
- 能加载 `PNG/JPG` 纹理
- 场景中包含 `5 个以上独立模型`
- 支持 `方向光 + 点光源 + 聚光灯`
- 至少实现 `一种阴影映射`
- 支持 `WASD + 鼠标视角` 的第一人称相机
- 支持 `ImGui` 实时调参

在上述能力完成后，再根据精力补充增强项。

## 四、场景设计建议

### 1. 推荐场景类型
优先采用封闭空间感明确的室内或半室内结构，例如：

- 实验室
- 工作室
- 地下室配电间
- 游戏安全屋
- 半开放走廊教室

### 2. 推荐结构
建议采用 `单主房间 + 次级区域` 的布局方式，例如一个主房间搭配走廊、储物角或设备间。

### 3. 选择理由
- 更容易突出光照与阴影
- 模型组织更集中，场景不易失控
- 更容易自然满足“多个独立模型”的要求

## 五、系统模块设计

### 1. 程序框架层
- GLFW 窗口创建
- GLAD 初始化
- OpenGL 状态管理
- 主循环与帧更新
- ImGui 初始化与渲染

### 2. 资源管理层
- Shader 管理
- Texture 加载
- Mesh 数据组织
- Model/OBJ 读取
- 资源路径与缓存管理

### 3. 场景组织层
- 场景对象列表
- 模型实例化
- 变换矩阵管理
- 材质参数绑定
- 场景布局配置

### 4. 渲染表现层
- 基础 `Phong` 或 `Blinn-Phong` 光照
- 方向光、点光源、聚光灯
- 阴影映射
- 深度贴图生成与采样
- 材质高光与发光表现

### 5. 交互控制层
- 第一人称相机
- 键盘与鼠标输入
- GUI 参数面板
- 光照、阴影与环境参数调节

### 6. 增强效果层
以下效果至少选择一项：

- 点光源衰减
- 聚光灯边缘平滑
- 动态风扇或钟摆
- 简单粒子效果
- 基础碰撞限制

## 六、推荐实现顺序

### 1. 最小运行骨架
- 创建窗口
- 初始化 OpenGL
- 接入 ImGui
- 实现摄像机移动
- 显示测试模型或测试几何体

### 2. 资源加载可用
- 完成 Shader 类
- 完成 Texture 加载
- 完成 OBJ 模型读取
- 成功渲染 1 个带纹理模型

### 3. 场景可展示
- 导入不少于 5 个模型
- 搭建室内主体结构
- 完成地面、墙体、主要家具或设备摆放
- 建立统一材质表现

### 4. 光照系统可验收
- 加入方向光
- 加入点光源
- 加入聚光灯
- 在 ImGui 中实时调节参数

### 5. 阴影系统可验收
- 优先实现方向光阴影映射
- 完成深度图生成与采样
- 修正常见阴影伪影
- 保证主要物体投影正确

### 6. 增强项补强
在主功能闭环之后，再完成一个增强项：

- 点光源衰减
- 聚光灯平滑边缘
- 旋转风扇
- 简单粒子效果

## 七、两人协作分工

### 1. 成员 A：程序与渲染主负责人
负责内容：

- 工程搭建与依赖配置
- OpenGL 渲染框架
- Shader / Texture / Camera / Model 类
- 相机与输入系统
- 光照模型实现
- 阴影映射
- ImGui 调参面板
- 最终联调与演示版本整合

交付物：

- 可编译运行的主程序
- 渲染核心源码
- 参数调节界面
- 最终演示可执行程序

### 2. 成员 B：模型与资源主负责人
负责内容：

- 场景主题与视觉参考
- 室内主体与道具建模
- OBJ 导出与拓扑检查
- UV 展开
- PNG 贴图制作
- 模型原点、朝向、尺寸统一
- 模型资源说明文档

交付物：

- 至少 5 个独立模型
- 对应 PNG/JPG 贴图
- 统一命名的资源目录
- 模型说明表

## 八、协作接口规范

为降低联调成本，建议从一开始统一以下规范：

- 坐标轴约定：建议 `Y-up`
- 尺寸单位：建议 `1.0 = 1 米`
- 模型正面方向统一
- 文本文件统一使用 `UTF-8`
- 文件命名使用英文小写与下划线

推荐资源目录结构：

```text
assets/
├─ models/
│  ├─ room/
│  ├─ desk/
│  ├─ chair/
│  ├─ lamp/
│  └─ cabinet/
├─ textures/
└─ shaders/
```

单个模型建议独立放置：

```text
assets/models/chair/
├─ chair.obj
├─ chair.mtl
└─ chair_albedo.png
```

## 九、敏捷推进原则

本项目不强调固定时间排期，而采用“先形成最小可验收闭环，再逐步增强”的推进方式。

### 1. 优先打通主链路
- 能打开窗口
- 能移动相机
- 能显示 ImGui
- 能渲染 1 个模型

### 2. 尽快形成可验收版本
- 模型数达标
- 纹理生效
- 三类光源可演示
- 阴影效果可见
- 相机漫游稳定

### 3. 再做增强与打磨
- 材质质感细化
- 阴影质量优化
- 参数面板更完整
- 增加动态元素
- 调整场景氛围

核心原则是：任何阶段都优先保证“当前版本可运行、可展示、可验收”。

## 十、风险与应对

### 1. OBJ 导入或材质不生效
应对方式：
- 先用 1 个简单模型打通完整加载流程
- 再逐步扩展到全场景资源

### 2. 模型尺寸和坐标不统一
应对方式：
- 提前统一建模导出规范
- 必要时在程序侧添加缩放与旋转修正

### 3. 阴影映射难度较高
应对方式：
- 优先完成方向光阴影
- 不一开始追求多光源阴影全覆盖

### 4. 联调时资源频繁变动
应对方式：
- 固定目录结构与命名规则
- 避免路径与文件名频繁修改

### 5. 效果堆积导致主功能未闭环
应对方式：
- 始终先守住最小可验收功能集合
- 所有增强项都放在主功能完成之后

## 十一、预期成果

- 一个可运行的室内三维场景程序
- 不少于 `5` 个独立模型及其纹理资源
- 支持实时光照、阴影和第一人称相机
- 支持 ImGui 参数调节
- 一套完整的课程汇报与答辩材料
